# Brand Website Storytelling

Use this skill for new brand websites, landing pages, campaign pages, and substantial visual refreshes. Do not apply it to ordinary admin screens or isolated component fixes unless the user asks for a brand/story treatment.

## Brief and content

- Read the supplied business facts, assets, existing site, and repository conventions first. Ask only for information that materially changes the result.
- Work in guided mode when the user wants review points; use autonomous/template mode when they ask to choose or assume. In autonomous mode, record assumptions and keep copy easy to replace.
- Preserve supplied facts and authoritative brand assets. Never invent testimonials, customers, awards, addresses, metrics, or other credibility claims. Mark fictional/demo content clearly.
- Keep copy, calls to action, links, and media references in an editable content source rather than scattering them through animation code. A form is either wired to a real destination or explicitly labelled as a demo; never claim a message was sent when it was not.

## Visual direction

- Establish a compact style tile using the actual implementation tokens: logo treatment, palette, typography, buttons, links, representative content component, and imagery direction. Keep it editable where practical.
- Treat references as inspiration and extract typography, spacing, contrast, composition, materials, and motion. Do not copy proprietary branding or artwork wholesale, and do not redraw an official logo merely to fit a new style.
- Before producing substantial motion, present a concise `Visual Story` table with exactly `Scene`, `Visual story`, and `Website copy` columns. Include meaningful transition beats when the story needs staged reveals, then describe scroll pacing in viewport heights and the intended holds.
- Choose the simplest architecture that tells the story: normal flowing sections, one pinned image/sequence stage, or connected sequences with a verified matching frame. Do not force every site into an endlessly pinned hero.

## Media and motion

- Use the user's requested provider and existing project workflow. Higgsfield or another media provider is optional: first verify that the required generation tools and account access are actually available. A prompt or skill does not create that access, authorize purchases, or change account settings.
- If generation is unavailable, continue with suitable supplied assets, local placeholders, or a still fallback and state the capability gap once. Never claim that an asset was generated or visually inspected when it was not.
- For connected scenes, preserve subject identity, geometry, framing, lighting, scale, and motion at each seam. Inspect outgoing and incoming frames together; a reference frame does not guarantee continuity.
- Keep semantic HTML separate from rendered motion. Text, navigation, buttons, and labels must remain crisp, selectable, accessible, editable, and usable in both scroll directions. Do not hijack native scrolling.
- Bound frame loading and decoded-image memory, handle fast and reverse scrolling, resize and teardown, and retain a useful poster/still if media fails. Support reduced motion, constrained devices, and a way to skip a long story.

## Verification and handoff

- Validate the actual site at representative desktop and mobile viewports when browser tooling is available. Check readability, scene timing, clickability, fallback behavior, and ordinary forward/reverse scrolling; a build alone does not prove visual quality or smooth playback.
- Verify asset manifests, frame numbering, dimensions, posters, referenced paths, and measured file sizes. Separate measured asset size from actual loading-speed claims.
- Hand off the runnable preview/site, style tile, selected source assets, editable content, assumptions, asset provenance, important measurements, and observed limitations. Keep credentials and temporary signed URLs out of reusable deliverables.
